# Quickstart

Goal: a working plugin called `notes` that exposes a `Note` Filament resource. Run every command from the Laravel application root.

`{plugin_root}` below means `base_path(config('mksine.plugins_path'))` (default `plugins/`).

## 1. Scaffold

```bash
php artisan mks-plugin:make notes \
  --author="Your Name" \
  --description="Demo plugin"
```

This creates `{plugin_root}/notes/` with `plugin.php`, an empty `PluginInterface` implementation under the chosen namespace, Filament directories, and a Vite-ready `package.json`.

The generated `plugin.php` typically looks like:

```php
<?php

return [
    'id'           => 'notes',
    'name'         => 'Notes',
    'description'  => 'Demo plugin',
    'version'      => '0.1.0',
    'author'       => 'Your Name',
    'namespace'    => 'Plugins\\Notes',
    'plugin_class' => Plugins\Notes\NotesPlugin::class,
];
```

The companion class implements [`Miran\Mksine\Core\Plugins\Contracts\PluginInterface`](../src/Core/Plugins/Contracts/PluginInterface.php). For the full method list and what each one is for, see the [contracts reference](reference/contracts.md#plugininterface).

## 2. Discover

```bash
php artisan mks-plugin:discover
```

Discovery scans every directory under `{plugin_root}` for a `plugin.php` file and refreshes the cache at `bootstrap/cache/mks_plugins_discovery.php`. Add `--clear` after major changes.

## 3. Install and activate

```bash
php artisan mks-plugin:install notes
php artisan mks-plugin:activate notes
```

These commands manage rows in the `mks_plugins` table and call your `install()` and `activate()` lifecycle methods. If `boot()` throws, the plugin is marked as boot-failed and disabled until you fix it; check `storage/logs/laravel.log` and the `mks_plugins.boot_error` column. See [Plugin lifecycle](guides/plugins/lifecycle.md).

## 4. Add a model

```bash
php artisan mks-plugin:make-model notes Note --migration
php artisan mks-plugin:migrate notes
```

The first command generates `{plugin_root}/notes/src/Models/Note.php` and a migration under the plugin’s `database/migrations/`. The second runs only that plugin’s migrations. See [Models and migrations](guides/plugins/models-migrations.md).

## 5. Add a Filament resource

```bash
php artisan mks-plugin:make-resource notes Note --model=Note
```

The plugin’s Filament resource directory is auto-loaded once the plugin is active; no manual panel registration is needed for resources, pages, or widgets generated by these commands. See [Filament resources](guides/plugins/filament-resources.md).

Generate Shield permissions for the new resource per your app’s convention (typically `php artisan shield:generate --resource=NoteResource`) and assign them to the appropriate role.

## 6. Visit the panel

Log in to the Filament panel as a user with the `Note` permissions. The new resource should appear in navigation, and create/list/edit should work.

## 7. (Optional) Frontend assets

If your resource ships custom CSS/JS:

```bash
cd {plugin_root}/notes
npm install
npm run build
cd -
php artisan mks-plugin:publish notes
```

Output lands at `public/plugins/notes/`. Commit that directory if production has no Node toolchain — see [Assets and Vite](guides/plugins/assets-vite.md).
